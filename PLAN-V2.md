# План V2: разбор, слой кандидатов из базы знаний, выбор, сертификат

Схема (вариант 2 из PLAN.md, доведённый до конца):

```
предложение
  -> [нейронка] разбор в предикатно-аргументную структуру (GF-подобную): предикат, аргументы, сорта
  -> [формальный слой] конфликт типов? если да, пространство прочтений = слой над референтом:
        маршруты по графу коэрсий, определённые для данного референта в базе знаний,
        склеенные по декларированным эквивалентностям
  -> [нейронка] выбор элемента пространства (или Retain / Family при неопределённости)
  -> [сертификат] разбор + выбранный маршрут + свидетельства
  -> [Agda] проверка против снимка базы знаний
```

Принцип: нейронка порождает только структуру (разбор) и делает выбор. Допустимость выбора, число различных прочтений и
отсечение прочтений, которым противоречит база, определяются формальным слоем. Выбор вне пространства невозможен по построению.

## Что гарантируется и что нет

Гарантируется: выбранное прочтение допустимо по типам, согласовано с разбором и истинно в снимке базы знаний. Число различных прочтений
вычислено, а не оценено.
Не гарантируется: верность разбора и верность выбора среди допустимых. Это эмпирические показатели, их мерим отдельно.
Для типов без базы знаний (пять из шести типов ConMeC) проверка остаётся структурной, это пишем явно.

## Этапы

### E0. Данные и привязка к базе знаний (топонимы)
- Скачать ReLocaR и SemEval-2007 (метонимия, локации), проверить лицензии, посмотреть формат разметки.
- Привязка названий к Wikidata (QID): сначала по готовым ссылкам, иначе поиском по метке; считать долю непривязанных.
- Выгрузить локальный снимок: для каждого QID страна, столица, правительство, институции в этом месте, спортивные клубы, события.
  Снимок кэшируется в файл, при проверке сети не нужно.
- Критерий готовности: доля привязанных примеров, 20 просмотренных вручную привязок.

### E1. Сорта, предикаты, ограничения выбора
- Сорта для топонимов: Place, Institution, Government, Team, Event, People (минимальный набор из разметки датасетов).
- Лексикон v2 (JSON, генерирует Python и Agda как в v1): рёбра Place -> Institution (seat, gov), Place -> Team, Place -> Event;
  правила эквивалентности (capital;govOf равно gov и подобные), непустые левые части, укорочение.
- Ограничения выбора для предикатов: какой сорт требует предикат и аргумент. Источник: LLM-разметка (со схемой вывода)
  на словаре предикатов датасета с проверкой выборкой вручную; без внешних лексиконов.
- Критерий: лексикон проходит валидацию и Agda-проверку, ограничения покрывают не менее 90% предикатов выборки.

### E2. Нейронный разбор
- LLM (Qwen2.5-7B в Colab или API-модель) выдаёт структуру: предикат, аргументы с id констант и сортами, роль целевого слова.
  Вывод в строгом JSON по схеме, затем проверка типов лексиконом; невалидный вывод считается ошибкой разбора.
- Альтернативная базовая линия без LLM: UD-разбор (stanza) плюс правила (окно предиката). Нужно разрешение скачать модели.
- Метрики: точность предиката и аргумента, доля валидных разборов, ошибки по типам.
- Критерий: доля валидных разборов не ниже 90% на dev.

### E3. Слой кандидатов (формальное ядро в Python, зеркало Agda)
- Обнаружение конфликта типов: сорт аргумента не равен сорту, требуемому предикатом.
- Пространство прочтений: маршруты из сорта константы в требуемый сорт длиной до k, определённые для референта в снимке.
- Приведение к нормальной форме по правилам (переписывание), склейка эквивалентных маршрутов в одно прочтение.
- Отсечение прочтений, у которых нет ни одного референта или для которых предикат ложен в снимке (по выбору: жёсткое или мягкое).
- Различимость прочтений: свидетельства различия (Apart) для пар, свидетельства равенства (Same) для склеенных.
- Тесты: Python-реализация сверяется с Agda на синтетических случаях (результаты зеркала равны вердикту Agda).
- Критерий: на выборке 100 примеров размер пространства и склейки согласуются с ручным разбором.

### E4. Выбор из пространства
- Скорер выбирает элемент: принудительный выбор среди прочтений (A/B/C…) с перестановками, либо оценка каждого прочтения отдельно.
- Режимы: Resolve при уверенном выборе; Retain или Family при близких оценках или нескольких различных допустимых прочтениях
  с одинаковыми оценками (намеренная неоднозначность).
- Порог и полоса подбираются на dev. Интерфейс скорера из pipeline/scorer.py сохраняется.
- Критерий: выбор в 2–4 кандидатах не хуже скорера E4 на тех же данных до добавления слоя.

### E5. Сертификаты и Agda
- Расширить формат (notes/CERTIFICATE-FORMAT.md): добавить разбор, а не только маршрут одного аргумента.
- Генератор снимка Agda из выгрузки E0 (не более 10 элементов на сорт, аудит правил для снимка).
- Пакетная проверка, как в check_agda.py: принятые, отклонённые контроли, причины.
- Критерий: все корректные сертификаты приняты; испорченные контроли отклонены; время проверки на пакет.

### E6. Оценка
- Режимы: по документам, по неизвестному целевому слову, по неизвестному типу (где применимо).
- Метрики: точность выбора, точность разбора, доля Retain и точность в нём, число различных прочтений, доля сертификатов, отклонённых
  из-за ложности в снимке (то, чего не было раньше).
- Абляции: A (нейронка предлагает, логика проверяет), B (слой кандидатов без выбора нейронкой: по правилу), C (без базы знаний),
  D (без склейки по эквивалентностям). Показать, что каждый слой что-то даёт.
- Собственный размеченный набор 150–300 примеров с намеренной неоднозначностью и случаями, где различные пути существенны; разметка совместная.
- ConMeC как второй уровень: слой кандидатов из лексикона типов (как в v1), структурная проверка. Результаты v1 сохраняются.

### E7. Формальные доработки (параллельно, по необходимости)
- Режим Family в пайплайне (сейчас только в Agda): нужны снимки с различающими референтами.
- Сертификация выбора режима и исчерпываемость семейства: расширение формата или явное ограничение в статье.
- Прямые доказательства корректности построителя снимков, чтобы не запускать аудит для каждого снимка.

### E8. Статья
- Структура: постановка, формальное ядро и сертификат, слой кандидатов, оценка, абляции, ограничения.
- Рисунки: схема, пример Fleet Street или Brussels с пространством прочтений, таблица абляций.

## Порядок и зависимости

E0 и E1 идут первыми (данные и лексикон), E2 может идти параллельно. E3 зависит от E1. E4 от E3 и E2. E5 от E3. E6 от всех.
Первый вертикальный срез: 30 примеров ReLocaR с привязкой, лексикон v2, разбор вручную, слой кандидатов, выбор, сертификат, Agda.
Срез нужен до масштабирования, чтобы найти ошибки формата.

## Риски

- Привязка к Wikidata шумная, часть примеров исключается; смещение отбора описывать в статье.
- Ограничения выбора, размеченные LLM, содержат ошибки; проверка выборкой и оценка влияния.
- Слой кандидатов может оказаться слишком большим при k больше 2: ограничить k и размер снимка (см. S0: аудит растёт как n^3.7).
- Нейронка-парсер ошибается, и сертификат это не ловит; честно разделять метрики разбора и выбора.
- Метки ConMeC и топонимных наборов различаются по схеме; не смешивать результаты в одной таблице.
- Токен GitHub после завершения работы отозвать.
